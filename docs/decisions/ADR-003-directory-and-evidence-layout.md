# ADR-003：目录规约与证据保存边界

- 状态：accepted（目录规约）；不表示 W2-A 已实现或验收。
- 批准依据：用户对 P-DOC 的回复“批准”，并要求明确 run 内 `.tmp` 是原子发布的必要例外。
- 批准确认者：用户；精确确认时间：未提供，不以文档保存日期替代。
- 项目根：`D:\MyPythonProjects\datainsight`。
- 授权效力：本轮仅授权新建 P-DOC 指定文档；本 ADR 不授权迁移、删除、修改代码、运行命令、安装或联网。

## 1. 决策

### 1.1 证据目录永久保留引用位置

`outputs/<阶段>/<run_id>/` 是运行证据目录。目录及已发布证据不得移动、删除、覆盖或回填，引用依赖其稳定位置。

- 正常、失败、修复前、修复后、合成与生产 run 均保留，失败历史不是垃圾。
- 重跑、修复验证、诊断和人工决定使用新的 run 目录，不复用已存在的输出目录。
- 新标准、新结果、新修复说明通过新文件或新 run 引用旧证据，不追改旧终态。
- 不用“整理目录”“节省空间”作为改动证据的隐含授权。
- run 内允许首次运行按已批准流程发布必需文件；这不等于允许事后修改已发布证据。

### 1.2 一般临时产物集中放置

新增的一般落盘临时产物只允许位于：

- `outputs/_scratch/`：需要落盘的工具工作产物、受控中间文件。
- `.cache/tmp/`：当前进程可控临时文件。

不得散落项目根，不得使用 C 盘作为新增项目文件、环境或可控缓存的默认目标。使用前须核对实际路径，并遵守当批动作许可；目录约定不是创建、执行或清理权限。

这里的“临时产物”是工具运行必需的中间文件，不包括第 1.4 节禁止落盘的对话内容。文档草案的正式版本不是临时文件，应在批准的 `docs/` 路径保存并明确标注 draft。

### 1.3 run 内 `.tmp` 是原子发布的必要例外

**run 目录内用于最终状态原子发布的 `.tmp` 是必要例外，不是遗漏，也不是待清理项。它不能迁到 `.cache/tmp/`。**

理由与本项目约束：原子改名必须保持临时文件与目标文件在同一文件系统；本项目进一步固定为同一 run 目录，使临时文件和目标文件处于同一目录／同一文件系统，避免跨卷移动或复制破坏原子发布。`.cache/tmp/` 不能代替这一发布位置要求，即使当前两个目录恰好都在 D 盘。

现有实现依据：`src/datainsight/__main__.py` 的 `publish_final_status`，在目标 run 内写入 `final-status-<status>.tmp`，完整写入并 flush／fsync 后重命名为 `final-status.json`。本 ADR 只规定该位置与语义，不重新判定 W1 原子发布实现，也不扩大其并发／系统隔离保证。

例外严格限定为：

1. 用于发布本 run 最终状态或其他已批准的原子发布目标，不得把一般草稿、日志草稿、调试文件混放 run。
2. 临时文件必须与发布目标位于同一目录／同一文件系统；文件名、目标和操作均受输出边界限制。
3. 成功重命名是运行发布协议中的必要操作，不是搬移证据目录或事后覆盖证据的授权。
4. 只有已发布的合法终态文件及其必需证据能证明运行终态；残留 `.tmp` 不能解释为 success。
5. 发布失败留下的 `.tmp` 原位保留，不能自动清理、迁移或改名伪造成功；后续处置需独立批准。
6. 同目录布局是原子发布的必要条件之一，不凭布局 alone 宣称具有全系统崩溃恢复、并发攻击防护或持久化保证。

### 1.4 不落盘的内容

以下内容不得作为项目文件、证据附件、日志或“会话存档”保存：

- 对话推理。
- 讨论过程。
- 临时文字草稿。

正式落盘只保存获批的方案、接口契约、验收草案／冻结标准、ADR、真实工具证据、简洁运行记录与验收结论。不得把完整聊天转录塞入这些文件。

### 1.5 结果入口

`docs/acceptance/results/INDEX.md` 是验收结果导航入口。

- 新增结果文档时，由获批的文档维护动作添加链接、阶段、记录性质及权威判定来源。
- 标准放在 `docs/acceptance/`；执行记录和最终验收结论放在 `docs/acceptance/results/`，不写回冻结标准。
- INDEX 是导航，不代替原始证据或最终验收文件。
- 生产计算证据与合成测试／修复后收尾证据分别列示，不合并成不存在的“修复后完整生产实测”。
- 链接用稳定相对路径；失效引用应报告，不通过移动旧 run 修复。

## 2. 既有存量与适用范围

- 所有 W1 证据原位保留。现有 run 内原子发布 `.tmp` 直接适用必要例外，不是需要搬迁的历史缺口。
- 不扫描或清理项目根、旧 run、venv 或系统缓存。
- W1 已固定的 DuckDB 引擎临时／扩展目录不由本文迁移；若未来需要改变其配置，须独立提出动作、影响及权限。W2-A 不启动 DuckDB，不新增引擎临时产物。
- W2-A 新增的一般工具临时文件遵循第 1.2 节；终态发布遵循第 1.3 节。实现和验证仍待单独授权。

## 3. 权限与变更

P-DOC 仅授权新建：

- `docs/W2-A-plan-v1.md`
- `docs/acceptance/W2-A-v1.md`
- 本 ADR
- `docs/acceptance/results/INDEX.md`

这不授权修改既有标准、W1 总结、历史执行记录、源码、配置、测试、原始数据或证据。未来 ADR 变更保留本版依据并记录新批准，不默默放宽保存规则。

## 4. 验收依据与影响

本轮只交付目录规约文件，不执行发布、故障注入、迁移或清理测试。W2-A 详细验收草案必须覆盖：旧 run 不变、已存在输出拒绝、一般临时路径约束、同目录发布例外、残留 `.tmp` 非成功及 INDEX 导航。

本决策不重新开启 W1 B01–B09，不改变其通过判定，不补造历史生产终态。
