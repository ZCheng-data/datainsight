# ADR-010：产品v2三条草稿通道方向与当前无模型S6

> 技术条款的判定由规划／验收方负责；用户确认的是范围、目的与验收安排，以及技术判定由谁承担。用户不对未逐条验证的技术条款承担认证责任。

- 状态：accepted（产品v2正式方向登记与当前S6路径）；非v2技术契约冻结、实现／联网／付费授权。
- confirmation_actor：用户。
- confirmation_basis：用户要求正式登记执行后解释草稿、入库前方法候选和入口翻译为下一产品版本v2方向，本轮不实施；同时要求准备当前无模型S6人工确认。
- confirmed_at：not_provided。
- recorded_at：null；recorded_at_source：not_available；recorded_at_status：unavailable。
- recorded_at_reason：本批仅文件工具，没有可信精确记录时刻，不取时或估计。
- authorization_scope：正式方向／ADR、W3最终验收及无模型S6准备文档新建，INDEX更新；不改原run／frozen／源码，不运行、外发、付费或代作S6决定。
- bound_versions：ADR-003／005／007／008／009、W3-v2 frozen、现有定位基线；旧W2-B2-v1和C205缺口保留。

## 1. 版本和现行路径

“产品v2”是下一产品能力版本，**不是**W3-v2验收标准版本，二者不混称。当前案例使用已验收确定性结果和宿主草稿，以无模型S6人工业务解释确认完成；v2方向不会成为当前S6的依赖或阻塞。

W2-B2真实方案解释接入仍停止续作，不恢复ADR-004／006的旧请求，不把方案解释权限迁移成结果解释权限。当前W3及其S6收尾不调用本地／远端模型。

S6是真正用户业务解释决定；技术通过、文档批准、报告存在或“继续”都不能代替实际批准。该人工门完成后才能称指定案例S4→S5→S6闭环；网络发布仍独立。

## 2. 正式登记的三条v2方向

| 方向ID | 产品阶段归属 | 已确认方向 | 当前状态 |
|---|---|---|---|
| V2-EXPLAIN | 产品v2的W4／S6可选解释草稿部件，位于S4计算和S5技术通过之后、S6人工决定之前 | 模型基于工具结果、已批口径及限制转为业务解释草稿；不能计算、新增指标／方法或批准行动，仍待人审 | 正式方向已登记；专项技术契约／W4模型标准未制定、未冻结、未实现／验收；无调用许可 |
| V2-METHOD | 产品v2的W5-B方法库发现／发布，服务未来S2／S3候选，位于方法执行资格授予之前 | 模型提出未注册候选→人审→明确前提／口径→确定性实现／测试→版本发布入库；执行只用已批库 | 方向已登记；原F-METHOD归属更新为产品v2；专项流程／代码未实现、未验收，未注册方法不可执行 |
| V2-INTENT | 产品v2的W5-A／S2入口翻译，先于确定性前提诊断及S2决定 | 自由文本→封闭结构化意图草稿→人确认；模型为执行前意图草稿例外，不扩大意图空间或授予执行权 | 方向已登记；原F-INTENT归属更新为产品v2；专项接口／提示／校验未设计冻结、未实现／验收 |

这是归属而非工期／一次实现整版承诺。实施顺序须在当前S6闭环后按价值、依赖与风险另行选定；当前没有开放问题空间或模型自动生成SQL许可。

原F-PATH受控问题路径入口缺陷登记保持，是入口可用性前置候选，不因本次三项登记消失、不本轮实现。它也不能被入口翻译层替代或借此允许任意路径。

## 3. 对ADR-008的精确方向变更

保持封闭方法执行、工具算数、人工门、原数据只读及必要证据基线不变。

ADR-008中模型仅在入库前方法通道、入口翻译为执行前例外的方向，**在未来产品v2增加“执行后的解释草稿”第三条例外**。它只读经核验的工具结果／口径／限制，无计算、方法发布、业务决定或执行权限。

此处批准的是存在这一未来部件的方向，不是完整技术设计可行性认证，也不是当前运行许可。不能修改已验收W3渲染或插入模型就继续按旧标准称通过。

## 4. V2-EXPLAIN开工前的必需安排

- 本ADR登记方向／角色例外；后续准确provider／endpoint／mode、输入内容、声明边界、风险／计费安排若形成新增决策，另有必要ADR，不能靠此方向通用授权。
- 新建专门W4／S6模型解释方案、技术契约及验收标准并冻结；当前无模型S6标准不能替代模型能力验收。若当时无模型标准已frozen，模型版本另版，保留无模型版本，不回写旧结果。
- 只能使用经核验的必要聚合／schema／已批口径，外发payload白名单和别名本地映射；不发送整个本地报告／路径／SQL／数据hash／原始行／标识或密钥。
- 数值由工具引用、渲染和校验；模型不计算、舍入或产生新数字，不生成订单／支付／转化／因果效果等无依据结论。自由解释不能由结构检查认证全部语义，仍为草稿。
- 最小反向覆盖错误引用、工具外数值、口径改变、无依据结论及伪批准；采用必要性基线，不恢复全产物审计、扫描范围报告或精细token证明堆叠。
- 未来付费风险、budget／真实usage／结算与协议另版；本地预算门只约束请求次数、已知消费与后续资格，不能宣称在途单次费用硬封顶；未知计费暂停，风险许可准确。
- 真实摘要工具读取、完整payload外发、凭据来源、付费单次请求分别获许可；旧C205仍未满足，不因新角色例外判其通过。未经必要新版本批准不能绕过现有关闭入口。

DeepSeek产品选择保持，但不猜准确model ID、余额、费率或费用。本ADR不自动联网查证、下载、安装或probe。

## 5. 当前S6不依赖模型

当前已验收草稿可供用户在本地审阅。业务确认限“指定版本和原始记录口径下的固定行为代码计数及明确限制”，不增加业务效果或行动推论。用户可以批准限定解释、拒绝或取消，不能默认批准。

推荐本案例用独立正式文档记录人审决定和已验收报告hash，不建设新S6自动化引擎；具体安排和最小标准为新draft，见[无模型S6方案](../W4-S6-no-model-plan-v1.md)。这是候选记录方式，等待安排确认与实际业务决定；本ADR不替用户确认报告，也不认证尚未执行的记录检查。

项目定位和证据基线保持；正式登记见[产品v2方向](../project-v2-directions-v1.md)。本批不改旧ADR、定位文档、frozen、run或源码。
