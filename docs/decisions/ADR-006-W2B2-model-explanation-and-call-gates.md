# ADR-006：DeepSeek 有限方案解释、外发门与单请求预算边界

> 技术条款的判定由规划／验收方负责；用户确认的是范围、目的与验收安排，以及技术判定由谁承担。用户不对未逐条验证的技术条款承担认证责任。

- 状态：accepted（闭环方向与责任边界）；详细方案／标准当前proposal／draft，尚未冻结。
- confirmation_actor：用户；confirmation_basis：用户对一次有界DeepSeek解释及三份文档新建的请求回复“确认”。
- confirmed_at：not_provided；recorded_at：null；recorded_at_source：not_available；recorded_at_status：unavailable。
- recorded_at_reason：本轮文件工具未返回可信精确记录时间，无取时命令权限，不以会话日期或旧运行时刻代替。
- authorization_scope：仅新建本ADR、W2-B2方案和验收草案；不授权实现、运行、联网、凭据读取或付费请求。
- 前置：W2-B1通过，确定性候选／S3记录为已验收基线，不把本ADR当新运行证据。
- 项目根：`D:\MyPythonProjects\datainsight`。

## 1. 决策：模型只解释已确认方案

W2-B2只做一次有界DeepSeek方案解释，不更改封闭候选集、指标口径、S3决定或生成新分析方法／数据结论。上游重新通过verify_review，并要求approve；旧批准绑定变化停止，不自动重新审核。

程序定义方法／口径、工具提供数值与证据、人作业务选择。模型只能组织已有前提、口径和限制，不执行SQL、不清洗、不计算、不批准行动、不自动推进S4。

理由：固定单方法已能验收，接入模型应证明有限可控解释能力，而不是为聊天演示把流程交给模型。无真实调用证据不称LLM闭环，离线基线继续可用。

## 2. 决策：最小必要payload并审核完整body

首次payload采用白名单宿主编译，仅必需behaviour/VARCHAR、固定任务／方法／口径说明、已核验row_count摘要与局部证据alias。其他字段、行为实际计数、时间极值、用户基数及分组均不发送；不以“聚合”自动视为匿名。

不发送本地文件／run／路径、源SQL／参数、数据内容hash、用户标识及其hash／伪匿名值、原始行、逐用户特征、密钥、自由文本样例或低频枚举。候选／receipt／验收文档整体不是payload。

完整body包括system/user、响应schema、model与发送控制字段；外发批准绑定实际body字节、目标、policy／价格／限额及上游版本。密钥头只在进程内装配，审批与日志不含值。

字符串扫描不等于匿名化证明；以白名单构造和严格schema为基础，受控敏感／指令哨兵测试用于限定范围证据，错误／trace也受约束。

## 3. 决策：单生成请求、无自动重试

先mock验证合法／反向与失败门，再核对实际DeepSeek配置并另获真实请求许可。每次明确许可只允许一次非流式生成尝试，不自动重试或schema修复请求，不使用额外付费probe。

provider/model必须产品显式配置，不由当前聊天模型隐式决定，不默默换模型／服务。准确endpoint／API model／能力当前未核对，不填猜值。

设计默认控制（不是实测）：自动重试0、总超时60秒、响应体64KiB上限、拒绝重定向。协议不相容应提出具体冲突，不自动放宽。超时取消本地等待不证明服务没有计费。

默认优先标准库有界HTTPS实现，不为接模型先建框架或安装SDK；可靠计数工具或其他真实协议确需新依赖时，独立提版本／来源／D盘安装权限。

## 4. 决策：预算可靠才发送

首次真实请求前必须取得准确费率／版本、实际余额依据、可靠完整输入token上界与可强制的全部输出计费上界，以及人明确批准的累计请求／token／费用限额。

充值计划20–30元不等于余额、调用预算或无限授权。不能按字符数估token，不能假定max_tokens覆盖所有model的计费输出／推理分类；缺可靠边界或价格／限额就不请求。

费用预留由工具使用最高适用费率计算，不依赖缓存折扣，十进制计量和保守向上预留明确。实际成本只用provider usage与有版本费率计算；没有账单证据不宣称核实实际扣款。

累计账本跨run／重启留存，不换scope／删除缓存归零。仅一个批准scope和单写者，最小排他防重复预留，不建复杂多用户系统。

## 5. 目录例外说明：预算run仅追加，不覆盖

账本放 `outputs/W2-B2/budget-<批准scope_id>/`，明确作为追加式预算证据run；不放可清理cache。reservation、attempt_started、settlement、unknown_charge、reconciliation事件独占发布且不可回填。

该选择**不改变ADR-003已发布证据不覆盖规则**：新增事件是本scope已批准运行协议的一部分，只追加新文件，不覆盖／移动／删除既有事件。故障.tmp仍同目录原子发布必要例外；残留或损坏账本停止，不自动清理／跳过。

预算scope、位置、事件命名与锁状态的具体写入范围须在实施／调用前获批。并发安全与追加顺序的设计不是当前已验证能力。

## 6. 响应与计费失败要分别处理

响应严格JSON、固定章节与引用alias，numeric_mentions仅value_ref，由宿主引用工具值；额外指标／新方法／工具外数字／SQL／批准字段拒绝，不静默补修或再请求。

解释自由文字只是structurally_valid_draft，仍human_review_state=pending。JSON／显式数值／常见越界检查不能证明所有语义正确或隐含误导不存在；不把结构校验当业务结论认证。

provider错误、拒答／截断、invalid结构／引用、usage缺失／不相容、超时或超预留均有受控状态。解释失败可能仍有真实费用；消费事件不删除，不当费用零，不自动重试。

计费未知保留风险额度并暂停付费，后来只通过另批新事件补核，不追改旧unknown。结算／收尾失败不留下成功最终状态。

回复／错误body非可信；有界内存检查敏感回显，被禁止内容不得落盘或回显。保存安全reason、可用usage及范围，不保存raw密钥头或违规rawbody。合法校验后响应与解释草稿可以在获批run保存，但不等于批准发现／行动。

## 7. 权限与历史边界

- 本轮只确认方向和文档新建。详细接口、payload、账本与验收安排在方案／标准审阅后冻结；准确model／费率／限额首请求前独立核对配置。
- 实现、mock、资料／余额核对、policy、prepare、外发、单次call与结果文档权限分别取得；相邻步骤可以在完整披露后同次批准，但不能从“确认方案”隐含获得。
- 不读密钥值到提示词，不读取全环境；用户从批准进程来源配置，不贴聊天。
- 保留W1、W2-A、W2-B1标准／代码／全部旧证据；不重新验收，不重跑生产CSV，不迁移历史confirmed_at或上游schema。
- 新授权按ADR-005区分confirmed_at与recorded_at；历史S3approve不是本轮外发或费用许可。
- .tmp／scratch／INDEX规则遵循ADR-003；不落盘对话推理、讨论或临时文字草稿。

本ADR不选择具体API model ID、费率、余额或累计数字限额，不证明能力、token、usage或成本已经实测。不授权W2-B2执行、清洗、S4或外部报告发布。
