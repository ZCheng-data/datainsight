# ADR-008：封闭意图定位、必要证据基线、W2停止续作与W3边界

> 技术条款的判定由规划／验收方负责；用户确认的是范围、目的与验收安排，以及技术判定由谁承担。用户不对未逐条验证的技术条款承担认证责任。

- 状态：accepted（下述方向、证据原则和阶段边界）；W3新详细契约／标准仍为draft，未运行／未验收。
- confirmation_actor：用户。
- confirmation_basis：用户明确采纳定位、扩展证据判据、预算限定、W3／S6边界、唯一方法结论范围、W2停止续作及后续方向登记八项边界，并要求合批落盘。
- confirmed_at：not_provided。
- recorded_at：null；recorded_at_source：not_available；recorded_at_status：unavailable。
- recorded_at_reason：本批仅文件工具，没有可信精确记录时刻，不运行取时命令或估计时间。
- authorization_scope：仅项目定位／基线、此ADR、W2最终状态、W3方案／标准／low交接新建及INDEX导航更新；无功能／配置变更、运行、真实数据／画像摘要工具读取、网络／凭据／API或付费许可。
- bound_versions：ADR-003／005／007；W2-A-v1、W2-B1-v1、W2-B2-v1及权威结果原位保留。

## 1. 定位与执行平面

采用“**面向封闭分析意图、提供可复核结论与证据的受控分析系统**”。需求诊断、方法前提检查、研究方案和指标口径审核作为前置能力；不使用无条件的“能证明结论可信”。

数值由确定性工具产生，执行只用已审查、测试、批准发布的封闭方法。方法审查、计算对照、版本身份、适用前提和S5校验共同支撑有限范围的可复核性；不认证源数据真实性、天然业务语义、总体代表性或因果效果。

方法模型仅在入库前参与未注册候选。未来使用模型的入口翻译明确为执行前意图草稿例外，不能获得直接执行权、替代人工选择或扩大封闭intent。

## 2. W2-B2停止续作与旧frozen

本ADR对**未来工作方向**替代ADR-004／006中继续真实模型解释接入的安排：停止W2-B2真实解释接入续作，解除W3对模型解释／C212真实调用的依赖。保留DeepSeek为未来获批模型部件的产品选择，不批准新的model／endpoint／mode。

W2当前结案措辞：**离线基线通过、阶段停止续作、W2-B2整体未验收／真实调用暂停。** 这属于方向收尾，不是全部W2条款技术通过。

- W1、W2-A、W2-B1既有通过保持。
- W2-B2 L1和限定tokenizer静态补证的限定通过保持。
- W2-B2-v1仍frozen，C205未满足，C212未完成；不删条款、不追改旧结果、不补造真实调用／usage／费用证据。
- 旧实现中的真实入口关闭保持，不改代码移除门，不重新运行或补计数证据。
- 未来模型调用的风险／预算／协议另版及另行授权，不能用本ADR算旧C205通过。

## 3. W3及后续的新证据基线

必要性判据：缺少它会导致错误结论、越权／泄露、不可逆损坏或未授权费用→必要；仅改善审计便利→不要求。

精简的对象是新批次的证据要求，不是既有安全检查、已发布证据或冻结历史：

| 新批次不要求 | 必须保留的对应底线 |
|---|---|
| 精确token上界证明、tokenizer精确计数、chat_template解析 | W3零模型调用，计数／usage／费用not_applicable；未来付费风险另版处理 |
| 跨run完整逐文件清单 | 本次结论必要输入／结果的解析引用、实际字节哈希与版本绑定 |
| 输出／错误／trace哨兵扫描范围报告 | 敏感内容不回显／不落盘，关键拒绝测试与安全reason_code |
| 同一结论反复独立恢复验证 | 消费入口验证、版本变化主要反向、唯一终态＋原子发布；不重跑以获得形式完备 |

保留批准路径、禁止覆盖、四道人工门、ADR-005责任／时间、确定性数值证据、方法前提、S5三层校验及本查询需要的资源／失败边界。哈希与原子发布不能替代业务语义、方法正确性或输入适用性。

旧核验接口内部已有的manifest／反复重建不借本ADR改写；W3可以复用，但不要求额外跨进程反复恢复报告或全历史清单。

## 4. 预算门限定与最坏风险

本地合一门约束请求／尝试次数、已知单次与累计消费及后续发送资格；累计显示复用现有账本思路。不要求以最坏token上界为未来新风险安排的证明，但不能宣称本地门硬限制在途单次实际费用。

未知计费暂停，不当零费用；已知费用超阈值阻止后续请求，保留消费。最坏可能损失账户可用余额，存在授信／自动补款时可能扩大；本地超时、输出参数或账本无法证明风险封顶。未来付费安排需明确账户边界、usage及结算适配、风险许可和新验收版本。当前没有费用数值、工具计算、账户／密钥访问或新请求许可。

W3完全不调用模型，包括本地模型；预算门、token、usage、provider费用均not_applicable，不启动预算账本、不推定余额。

## 5. W3证明场、报告迁移与独立S6

现有使用阶段已有历史生产画像／模板重跑、源前后身份一致、真实S2 accept及S3方案／口径approve；尚无完整S4→S5→S6真实业务结论闭环。

W3必须新增获批真实数据计算与S5执行／口径／边界校验，产出带证据的本地报告草稿；仅使用`M-BEHAVIOUR-RECORDS`。报告内容只允许行为代码原始记录计数及限定描述，不称订单／支付／转化／效果。

对原roadmap的变更：原W4-A的**报告草稿生成**提前至W3／E3，取代ADR-007对E3本地结果文档较窄的产物解释；不迁移S6人工业务解释决定，不改变真实读取／外发独立授权。

- G3.5：独立人工选择“不清洗／原始记录全保留”；本轮不支持其他策略，但不能默认批准。
- E3：一个合批执行／技术验收单元，S4计算＋S5三层校验＋本地报告草稿；人审状态pending。
- S6：W3之后独立人工业务解释确认；完成记录后才能宣称该案例完整S4→S5→S6闭环。报告存在、S5通过或W3通过均不是S6批准。
- 外发／发布仍另有动作许可；S6确认不自动授权网络。

W3零模型、不新增方法、双口径、自由文本入口、受控问题路径入口或自由SQL。数据身份变化使原批准失效时停止，不能为了推进改数据口径或重做W1／W2。

## 6. 后续阶段登记

正式清单见[项目定位与基线](../project-position-and-evidence-baseline-v1.md#5-后续版本登记本轮不实现)。阶段归属：

- W4-C／W2-A可用性扩展：固定问题路径硬编码改为受控路径；仍封闭intent。
- W5-A／S2入口扩展：自由文本→结构化意图草稿→人确认；可插拔执行前通道。
- W5-B／方法库版本扩展：未注册候选→人审→实现／测试→发布；与已批准注册库执行分离。

这些仅为方向登记，W3证明场与独立S6之后再确定具体范围；不是排期承诺或实现许可。原W4回归方向保持。

## 7. 实施与兼容

目录规约ADR-003、责任／时间ADR-005、受控合批及范围预授权ADR-007保持。每批一句话通知，范围／次数／命令未批准不执行；真实数据／画像摘要工具读取、外发／付费和人工门仍独立。

本批不改准备包或安装skill，不改旧handoff、标准、源码、配置、产物／缓存或历史confirmed_at。W3新增详细契约和数值资源设计尚未逐条确认，文档状态draft；后续冻结需用户确认范围／目的／验收安排，技术充分性由规划／验收方承担。
