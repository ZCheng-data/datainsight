# ADR-007：受控离线合批、范围预授权与 W3 批次重排

> 技术条款的判定由规划／验收方负责；用户确认的是范围、目的与验收安排，以及技术判定由谁承担。用户不对未逐条验证的技术条款承担认证责任。

- 状态：accepted（工作流规范及 W3 批次组织；不修改技术标准）。
- confirmation_actor：用户。
- confirmation_basis：用户提出两条降本建议，并对“受控本地变更可合批、范围预授权与 W3 重排”的说明及本轮文档请求回复“批准”。
- confirmed_at：not_provided。
- recorded_at：null；recorded_at_source：not_available；recorded_at_status：unavailable。
- recorded_at_reason：当前文件工具未返回可信精确时间，没有运行取时命令，不估计记录时刻。
- authorization_scope：本 ADR、W2-B2 离线审查及 L1 交接新建，INDEX 导航更新；不批准 L1 执行、W3 实现、数据读取或 API。

## 1. 合批原则：最小闭环以结果为单位

离线、可重跑、无中间人工决定门的工作，优先合并为一个结果闭环：明确范围内的实现／测试修改 → 合成测试与校验 → 证据整理 → 结果文档及 INDEX → 一次交回技术验收。

规划／验收方负责一次列全该闭环的相关验收项，执行方完整交回，不人为把每个小文件或文档更新都拆成一次新对话。不得以合批为理由一次生成整个项目、跳过反向测试或隐藏失败。

### 对“副作用”的澄清

本地代码编辑、合成 fixture 生成、日志与文档落盘也是副作用，但可以在精确预授权范围内合批。若所有写入都必须独立，合批原则会失效。

以下仍独立保留权限／决定门：

- 真实数据读取：包括生产 CSV 及真实画像／业务摘要证据的工具执行读取；文件审阅或旧阶段许可不自动授权新的计算／准备运行。
- 外发、联网／凭据访问、付费 API；不以本地许可推导网络权限。
- 人工业务决定：受理、路径／口径、清洗策略、业务解释和发布等。
- 破坏性或难逆操作、删除／迁移、旧证据变更、安装／新增依赖、未预授权的全局或外部状态变更。

“独立门”不等于将该门后无人工决策的每个内部步骤再拆批。例如真实数据读取许可明确涵盖一次 S4→S5 运行后，其内部校验与本地结果记录可连续完成，不需对每条 SELECT 再问一次。

## 2. 范围预授权模式

用户可在里程碑或明确续作开始时，一次性批准后续批次的精确范围与命令。预授权应写明：

- 里程碑／交接版本、批准人及确认依据。
- 可修改文件及允许的改动类别；保护文件／禁止操作。
- 合成输入、输出、临时目录、账本／锁状态的路径和命名规则。
- 实际命令及 cwd／环境；若执行入口尚未实现，明确作为批准的待实现接口，不声称已经存在。
- 批次数、允许重跑次数／原因、费用或资源限额、失效条件。
- 每批起始通知、失败停止点、交付物和一次技术验收安排。

获批后，执行方每批开始前用一句话通知本批目的、范围与命令；在批准范围内无需反复询问同一动作。通知不是新的权限，也不能把之前被拒绝的动作变为已批准。

### 仍需重新申请的情况

- 真实数据读取、外发／网络或人工决定门：逐次申请准确来源、动作及范围；技术预授权不替代这些许可。
- 增加文件／命令、新增依赖、提高上限、变更指标／冻结标准、超出限定修复范围。
- 真实运行发现的功能缺陷，其最小修复不在当前预授权范围内。
- 预授权次数耗尽、暂停／撤回、输入或批准绑定变化。

用户可随时叫停或撤回。执行方收到后停止启动下一步并尽可能安全取消当前动作；已经运行的命令不保证瞬时中断，不承诺撤销已经产生的效果。保留失败、部分及费用不确定证据，不自动清理或重新调用。

本规范是许可机制，不是当前任何具体批次的预授权。范围、命令及重跑预算未批准时，仍须等待。

## 3. W3 重排：一个独立门＋一个执行／验收批次

以下替代旧候选路线中将 S4 与 S5 分开的批次安排；不编辑准备包历史 roadmap，不改变现有冻结标准。W3 的具体方法、实现、资源边界与测试须后续规划并获批，当前没有 W3 执行许可。

### G3.5：独立人工策略决定门

- 明确选择不清洗，或批准具体受控派生清洗策略。
- 绑定数据、已选方案、指标口径、策略版本与影响；拒绝／取消停止。
- 不清洗也是显式选择。原数据只读，不把 S3 方案中的“保留原始记录”自动升级为 S3.5 决定。
- 决定记录按 ADR-005 保存；没有决策不启动后续计算。

### E3：S4 计算＋S5 校验＋本地结果文档

1. 事先批准本批代码／模板范围、精确执行命令、资源与输出边界、重跑上限。
2. 开始涉及真实数据的运行前，单独申请本次真实读取许可，绑定文件／版本及已确认策略；不能用预授权笼统覆盖未来任意读取。
3. 取得许可后，一句话通知，连续完成 S4 受信模板计算 → S5 执行／口径／声明边界校验 → 本地结果文档与 INDEX。
4. 工具保留各步骤独立状态／证据，在批次层汇总；不是将多个步骤混成不可审查日志。
5. 执行方一次交回，规划／验收方对这个最小闭环一次验收。

校验失败保留计算证据及失败状态，停止“成功交付”，按预授权范围决定是否允许有限回退；不得自动改口径、策略、模板集合或请求模型来凑成功。真实读取重跑仍需新的读取许可，即使合成重跑次数尚有余额。

合批不扩大 SQL 权限：仍仅批准的 SELECT／WITH、受信来源和资源／结果边界，无自由 SQL。数据／方案／策略变化使相关批准失效。

E3 不包含 S6 人工业务解释确认、外发或新的模型调用；这些门保持独立。

## 4. low 与 high 的工作分配

- high 规划／验收：给完整但有限的结果闭环、提前列明全部正常／反向证据、保护范围与停止点；审查一次完整交付，不按文件反复开启同一轮。
- low 执行：在已批准范围内连续实现、测试、汇总和记录，使用新 run；每批一句话通知，不自动升级模型／启动其他会话。
- 失败：先分清测试构造错误、证据缺口与功能缺陷；只有必要的最小变更才请求新增权限，不重发整项目。
- 成本／时长节约只可作工作流目标；没有实测对照不编造 token、金额或效率提升比例。

## 5. 不变约束与历史兼容

所有 frozen 验收条款保持，旧权限与 run 不回填。新工作流可由新交接采用，但不修改旧交接的历史批准，也不自动授权其余待办。

ADR-003 仍有效：证据目录不移动／删除／覆盖；一般临时文件集中；同目录原子发布 `.tmp` 是必要例外。ADR-005 的技术责任及确认／记录时间分离继续适用。

当前 W2-B2 下一步 L1 可合并“离线补测＋必要测试修正＋新证据＋结果文档”，实际修改文件、命令、次数及范围见其交接，另获用户执行预授权。真实协议核对、policy、实际准备／外发／调用仍保留准确许可门。
