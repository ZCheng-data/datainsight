# ADR-005：技术判定责任与用户确认时间记录规范

- 状态：accepted（记录与模板规范）。
- 批准依据：用户批准 W2-B1 验收结论落盘，并明确建议把本规范两条规则写入 ADR 或独立规范文件；本轮两条均采纳。
- 确认者：用户。
- confirmed_at：not_provided。
- recorded_at：null。
- recorded_at_status：unavailable。
- recorded_at_reason：本轮只使用文件工具；工具未返回精确记录时间，没有获批的取时命令或其他可信精确时间结果。不得以会话日期、文件名、历史运行时间或估计时刻填入。
- 适用边界：从本规范起的新记录、新模板；不回写冻结标准、历史文档或运行证据，不扩大当前 W2-B1 补测范围。

## 1. 决策一：用户授权与技术认证责任分开

凡涉及冻结验收标准或技术条款的新增记录／模板，明确写入：

> 技术条款的判定由规划／验收方负责；用户确认的是范围、目的与验收安排，以及技术判定由谁承担。用户不对未逐条验证的技术条款承担认证责任。

### 解释与应用

- 用户确认范围、目的、验收安排和职责分工，可以形成标准冻结与动作授权的依据；不意味着用户已经逐条运行、验证或认证技术实现。
- 规划／验收方负责制定可判定条款、核对证据充分性、发现冲突并作出通过／有条件通过／不通过结论，不能把技术缺陷或证据缺口转嫁为“用户已确认所以用户负责”。
- 执行方负责按授权实现、测试及保存真实结果，不得以用户批准交接代替技术运行证据。
- 用户的业务决定仍由用户作出：受理／补数／拒单、候选与指标口径选择、清洗策略、业务解释及外发。这与技术认证责任分离，不取消人工门。
- 用户对技术安排的确认不扩大执行权限；技术批准、当批动作许可和业务审核须分别记载。
- 标准一经冻结，技术判定方也不能以本责任声明为理由放宽标准；变更仍须保留旧版并履行原有批准及 ADR 程序。

适用于新增的冻结记录、涉及技术条款的 ADR、执行交接、验收结论及相应模板。纯导航入口可链接权威记录；若入口自身解释冻结或技术认证责任，则同样使用上述声明，不作相反表述。

## 2. 决策二：confirmed_at 与 recorded_at 分开

### 2.1 confirmed_at：用户提供的确认时间

- 用户明确给出字面确认时间：按原文记录字面值。必要时另存 confirmed_at_raw 或 time_precision，保留时区与精度的不确定性。
- 用户没有给出确认时间：confirmed_at 必须记为 `not_provided`，不能填工具操作时间。
- 用户给出模糊或缺时区的时间：保留字面值，不能擅自补日期、秒或时区。确需可比较的规范化时间时，另列 normalized_confirmed_at／normalization_basis，只有依据充分才填；不得覆盖原文字面值。
- 运行开始／结束时间、命令执行时间、文件 mtime、会话日期或 recorded_at 都不能证明用户实际确认时刻。

### 2.2 recorded_at：工具取得的记录时间

- 在新增记录的获批生成动作中，由工具独立取得实际记录操作时间，保存为 recorded_at，并记录时间来源，例如 recorded_at_source。
- recorded_at 不使用语言模型估计；不从历史运行时间倒推，不按文件名猜测。
- 无论用户是否提供 confirmed_at，recorded_at 都独立保存；**任何情况下不得用 recorded_at 冒充 confirmed_at**。
- 工具可取得精确记录时刻时使用带时区的时间，并说明是记录操作时间，而非用户消息时间。
- 工具未提供可信精确时刻时，recorded_at=null、recorded_at_status=unavailable，并给出 reason；不伪造、不自行执行未授权命令。该状态不是“已取得记录时间”，不宣称时间证据齐全。
- 后续如需补充工具时间，单独新增记录说明实际取得的时刻及范围；不能把后来的取时结果回填成原记录时刻，也不能覆盖旧证据。

本轮文档头使用上述 unavailable 表达是如实披露工具能力缺口，不把缺失当真实时间。后续有获批执行工具的生成流程应实际取得 recorded_at，不能将本次例外用作永久省略理由。

### 2.3 适用产物

适用于新的：

- 标准冻结／技术安排确认记录。
- S2／S3／清洗／交付等人工决定记录。
- 其他要求用户确认的授权、审核和产品产物。

confirmed_at 的 `not_provided` 仅表示确认时间未知，不表示没有确认。确认本身通过明确确认内容、确认者、确认来源、绑定版本和许可范围记录；时间与授权是否存在不能混为一谈。

## 3. 新记录／模板的最小字段

以下是文档模板契约，不是可执行代码、已安装 schema 或功能接口修改：

```text
confirmation_actor: <真实确认者>
confirmation_basis: <简洁的确认内容／可核验来源，不保存完整聊天>
confirmed_at: <用户字面时间；未提供则 not_provided>
recorded_at: <工具取得的记录时间；无法取得则 null>
recorded_at_source: <具体工具／输出引用；无法取得则 not_available>
recorded_at_status: available | unavailable
recorded_at_reason: <unavailable 时的原因>
authorization_scope: <此次确认／动作许可范围，明确不包含什么>
bound_versions: <数据／问题／方案／指标／标准等相关身份>
technical_responsibility: 技术条款的判定由规划／验收方负责；用户确认的是范围、目的与验收安排，以及技术判定由谁承担。用户不对未逐条验证的技术条款承担认证责任。
```

业务审核记录另外保存 decision、被选对象、明确确认项等；不以本规范生成默认批准。记录中只保留必要确认依据，不保存对话推理、讨论或完整聊天转录。

## 4. 历史兼容与当前补测边界

- 不修改 W1、W2-A、W2-B1 已冻结标准，不重新冻结或撤销已完成验收。
- 历史“未提供”文字、confirmed_at 中已存的工具操作时间及相应解释全部原位保留；不能把它们追改为用户时间或新格式。
- 引用旧记录时明确其既有时间语义。旧工具操作时间只作历史记录时刻说明，不因字段名叫 confirmed_at 就冒称用户给出字面时间。
- 本规范不改变当前功能 JSON schema、时间校验函数或审核 CLI。现有实现可能要求 confirmed_at 为带时区字符串；如未来需要采用新字段／not_provided，应在新的独立功能变更中明确兼容策略、接口及测试，并另获授权。
- **当前 W2-B1 补测仍只针对既有版本变化反向与已有输出保护缺口**；不加入时间字段重构、历史迁移或新的时间测试要求。
- 记录责任条款不改变任何 frozen 技术阈值、用例或通过条件。

## 5. 本轮交付与后续

本轮仅新增本 ADR、W2-B1 最终验收记录并更新 INDEX 导航。不改代码、测试、原数据、冻结标准或旧证据，不运行命令、不安装、不联网。

后续新增交接和验收模板引用本规范。功能记录采用新时间字段需独立规划／授权，不能借本次文档规范自动开工。
