- 批准依据：用户对 W2-B1“确定性候选方案＋S3 口径审核”、离线基线与随后 DeepSeek 接入的建议，以及仅新建方案／标准／本 ADR 的请求回复“批准”。

## 1. 决策与理由

### 1.1 一个闭环推进，不一次实现整个 W2

W2-B1 只实现确定性候选方案＋S3 口径人工审核的离线基线；W2-B2 再独立规划 DeepSeek 对合格候选的有限组织／解释与首次调用门。

理由：W2-A 当前已验收的是确定性诊断、固定合格方法及 S2 记录。先让“候选来自哪里、指标定义是什么、人是否确认”可复核，不先建设 provider SDK、预算系统或复杂框架。本阶段通过也不宣称实现 LLM Agent。

此拆分不取消 W2 使用 DeepSeek 的已确认产品选择，不重问领域、项目路径、D 盘规则或充值计划。预算计划不代表余额、费率、token或实际调用许可。

### 1.2 程序选择合格方法，候选可零

候选方法固定于源码注册表；规则／字段／粒度前提通过后才生成。未知方法、任意用户规则或SQL不获得执行资格。候选可为空，不凑数量，不按模型“看起来更好”添加未支持方法。

当前注册方法只承接 `M-BEHAVIOUR-RECORDS` 的原始记录固定桶分类计数。GMV、比例、严格漏斗、日期分组、因果或预测不纳入本闭环。

诊断规则身份与方案注册表身份分别保存；生成候选绑定S2、诊断、问题、数据及manifest，避免同名方法的定义变化被旧批准掩盖。

### 1.3 口径是审查对象，不是模型生成真值

候选必须显式给出事件／主体／粒度、计数对象／分母、窗口／时区、分类／过滤、空值、重复、维度、聚合及变换策略。当前候选采用读取契约的原始记录语义，固定桶、全文件版本窗口、不清洗、不去重、不生成比例或日期。

已有behaviours模板用于定义核对与证据引用，不在本阶段执行；不把候选的预期输出schema冒充已经计算的结果。

原始记录不能推为订单／支付；整数timestamp不能推为日期／时区／事件链路；没有字段／工具证据的结论保持缺口或未知。

### 1.4 S2有效性必须重新核验

W2-B1入口通过现有 `verify_decision` 与 `load_diagnosis` 重新验证receipt、诊断、manifest、终态与版本；另要求实际decision=accept，不仅是receipt格式合法。

request_data／reject／cancel、输入变化或缺终态都停止。用户批准规划不替代真实S2决定，也不替代当批执行权限。

新阶段的实际独立核验是后续运行验收内容；当前规划读取receipt不冒称已经运行核验。

### 1.5 S3人工选择与口径确认不可绕过

程序只生成候选。人明确选择候选并确认指标定义，或拒绝／取消。成功生成候选不是已经受理方案；缺选择／确认／匹配摘要不记录approve。

审核记录保存到新run，绑定候选／口径及上游全部相关版本，数据／问题／规则／注册表／候选／口径变化即失效。重启必须核对，不默认视为批准。

scope仅 `S3_plan_and_metric_only`，不授权清洗、计算、网络或外发。不变换原数据的说明不是自动S3.5清洗批准。

## 2. DeepSeek后续职责（W2-B2，未实施）

DeepSeek只能组织／解释程序提供的合格候选与引用，不创造新方法、指标或数字，不执行SQL、不替用户选择、改口径或批准后续动作。

首次真实调用前须核对：

- 明确provider／model ID及能力；不能用聊天客户端当前模型隐式替代产品配置。
- 严格结构化输出与字段／数字引用校验；非法schema、额外指标、未支持方法不得默默修成成功。
- 用户审核的schema／聚合payload；不得带绝对或相对路径、原始行、用户标识／哈希／伪匿名ID、逐用户特征、密钥。低频组／自由文本需明确处理，聚合不自动等于匿名。
- 真实费率版本、余额、累计请求／token／费用上限、跨run与重启账本，覆盖失败、超时、重试和未知计费。
- 当轮外发与调用授权；无法可靠计费／限额缺失则不付费调用。不默认把20–30元预算全用尽。

本ADR不选择准确API model ID、请求上限或价格，不假称外部能力／计费已验证。能力不满足时停在明确离线基线，不默默换模型或扩大调用。

输出使用新 `outputs/W2-B1/<run_id>/`；同目录原子发布`.tmp`按ADR-003必要例外保留。失败目录与旧证据不移动、删除、覆盖或回填。
