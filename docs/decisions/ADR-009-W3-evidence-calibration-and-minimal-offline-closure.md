# ADR-009：W3必要证据校准与最小离线收尾

> 技术条款的判定由规划／验收方负责；用户确认的是范围、目的与验收安排，以及技术判定由谁承担。用户不对未逐条验证的技术条款承担认证责任。

- 状态：accepted（证据校准、标准另版及限定收尾方向）；不是R3执行或真实读取授权。
- confirmation_actor：用户。
- confirmation_basis：用户要求按已批准必要性基线复核D301–D312；规划方给出前序继承、审计性矩阵删除与最小剩余集合后，用户回复“批准”。
- confirmed_at：not_provided。
- recorded_at：null；recorded_at_source：not_available；recorded_at_status：unavailable。
- recorded_at_reason：本批仅文件工具，没有可信精确记录时刻；不执行取时、不估计或借用历史运行时间。
- authorization_scope：本ADR、W3-v2、R2校准结果记录及R3限定交接新建，INDEX导航更新；不改源码／测试／配置／旧frozen／R2证据，不运行、不读取生产CSV或真实画像工具输入、不联网／凭据／API。
- bound_versions：ADR-003／005／007／008；W3-v1 frozen原位保留；R2-b原始证据与历史执行状态原位保留。

## 1. 决策与责任

沿用ADR-008基线：缺少它会导致错误结论、越权／泄露、不可逆损坏或未授权费用才必要；仅改善审计便利不要求。

W3-v1将必要防护过度展开为重复前序核验及细粒度证明矩阵。规划／验收方承担校准责任，不把用户标准确认当作技术充分性的认证，不把low的测试数量或未闭合清单当作验收结论。

新增[W3-v2](../acceptance/W3-v2.md)，作为后续W3验收的当前标准。唯一方法、原始记录口径、批准／版本／字节hash、路径及不覆盖、S5三层、唯一终态／原子发布、零模型与独立人工门不变。更改的是证明义务和离线／真实验收分层，不是为了让错误功能通过而取消防护。

W3-v1、原方案／交接及R2执行记录不改。W3-v2优先于它们对重复矩阵、计分方式和收尾证明的旧要求；未明确变更的功能接口、数据来源、资源设计及产物沿用W3-plan-v1。

## 2. 可继承与不再补测的范围

| 校准范围 | 继承依据 | 后续底线 |

| 完整上游变化／恢复／原因矩阵 | W2-B1 B101／B103／B104／B108及R2实际W3接入／拒绝 | 保留实际消费入口核验，不重新铺全S2／S3矩阵 |
| 路径链接／重解析完整矩阵 | W1-B B04、W2-A A02、W2-B1 B102；W3调用未改路径helper | 固定源、路径helper实际调用和当前hash必需；不宣称真实junction／竞争攻击认证 |
| 严格读取／桶语义组合穷举 | W1-B B02／B03／B05／B06、R2真实DuckDB＋独立csv／Counter | 新worker组装有对照；不重做所有已证组合 |
| 策略所有身份字段逐一变异 | R2明确决定、拒绝／取消、未知策略及绑定失效 | 新策略门有效批准和缺终态拒绝仍必需，不穷举全字段 |

继承只在被复用的实现／边界未改变时成立。后续若改路径helper、模板、上游验证或provider导入／发送路径，则对实际受影响的新路径补最小测试，不自动要求全项目回归。

不删除已有测试／旧证据，不为恢复“通过”状态覆写R2的batch-result。R2的97项passed是工具结果；runner固定填写incomplete／unmet不能单独认证覆盖，详见[校准记录](../acceptance/results/W3-r2-evidence-calibration-v1.md)。

## 3. 最小剩余离线集合

R3如后续准确授权，仅包含：

1. **D302缺终态**：合法策略正常消费基线→仅缺strategy run的final-status→执行入口拒绝，未读源／未查询／未发布success。必要原因：不能以部分receipt当有效人工策略。
2. **D305配置拒绝**：实际固定查询配置正常基线→仅观察到的局部配置不同→固定拒绝，不执行业务聚合、不成功交付。必要原因：不能假称资源和扩展配置已生效。
3. **D305总体deadline**：修复当前最后时间检查之后仍可能继续核验／落盘并success的问题，覆盖后置核验／写入拖延到截止后的拒绝，保留正常完整执行。必要原因：不能把worker受控冒称整个E3受控，不得超期后按已知过期状态发布成功。

只允许现有analysis.py／test_w3.py内实现必要时间检查和上述证据／runner校准，标准不扩展。R3不重建97项矩阵、不加D303链接矩阵或D310／D311穷举。

时间值保持180秒。要求合作式阶段／块检查、worker剩余预算与截止后不发布成功；不是OS级硬实时中断。阻塞文件系统调用或最终原子改名无法由Python检查保证瞬时撤回，失败收尾／回收可有已声明有限等待。不得为了消除这一未承诺能力建设全系统监控或放宽资源数值。

## 4. 离线／真实／S6验收分开

- 离线技术门：D301–D311对应离线证明义务及上述最小缺口闭合；继承证据＋当前受影响路径回归共同判定，不按case数量认证。
- D302真实决定和D301实际固定真实链核验在后续独立G3.5安排完成，不用合成批准代替。
- D312：真实读取独立获批后新增唯一方法真实计算／S5／草稿，是W3总验收必需项；未授权时记not_run，不使完整离线runner固定失败。
- 离线通过不授权G3.5／真实读取；W3总通过不自动S6。完整S4→S5→S6仍需随后独立人工业务解释确认。

## 5. 权限与成本

本次用户批准确定证据校准及落盘，不推定尚未列明的R3命令／batch_id／执行次数预授权。R3交接给出一次运行候选范围，执行者须先说明并取得准确许可；不复用耗尽的R2次数，不自动补齐、重跑、安装或提高限额。

G3.5真实核验链工具读取／人工决定、E3真实CSV读取、S6与外发仍各自独立。规划角色不实现、不执行，不创建Agent／Session。

产品W3零模型，计费not_applicable；开发辅助token／金额与补齐总耗时缺工具证据，记unknown，不把180秒设计值当预测，也不编造节约百分比。失败保留证据并一次交回high，不无限迭代。
