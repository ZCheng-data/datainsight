## 1. 一个闭环

重新核验S3 approve → 构造完整脱敏请求 → 明确外发与预算批准 → 持久预留 → 单次DeepSeek请求 → 严格响应／引用校验与真实usage／费用工具计算 → 本地待人工审阅解释草稿与证据。

不改变候选／方法／指标／S3决定，不计算新业务数值、不执行SQL、不读生产CSV、不清洗、不自动进入S4。先mock与门控，再独立真实调用；mock成功不能宣称付费或模型能力已验证。

固定真实S3输入与核验链按方案第2节。首次payload按第3节仅必需behaviour schema、固定方法／口径、已核验row_count与局部alias；不外发整个本地方案／receipt／SQL／路径或数据哈希。

普通证据在新outputs/W2-B2/<run_id>/；mock输入在outputs/_scratch/<batch>/<case>/；唯一批准scope追加账本在outputs/W2-B2/budget-<scope_id>/。事件不可覆盖；同目录原子发布tmp是必要例外，失败残留保留。所有路径／权限实际动作前明确，不扫描任意目录。

## 3. 测试与计费证据纪律

- 每个主要反向有合法独立基线，只变一个条件，断言准确阶段／reason_code及请求是否实际未发送，不用前一个错误掩盖后续检查。
- mock transport只做新受控fixture／调用观察，不访问真实危险网络／原CSV。真接口成功另有证据，不能把文档支持或mockusage当provider实测。
- 预算数值的算术由工具计算；价格本身绑定可靠来源，不猜实际余额／已充值。
- 发送前reservation／attempt持久化失败请求计数为0；发送开始后超时／不明计费保留风险额度，恢复不得自动重发或释放。
- 单个HTTP生成请求失败不自动重试；计数官方能力核对或余额访问另获批准，不混入免费准备／无计费声明。
- 账本事件仅追加不回填；单scope不能通过改run或重建账本绕过累计上限。未结算状态阻止后续付费直到另获核对许可。
- 单写者／锁使用批准D盘范围，失败不自动清锁；不宣称多用户分布式事务。
- 自由解释文字自动校验只证明结构和显式引用／常见越界控制，不能证明全部语义。validation_state=structurally_valid_draft、human_review_state=pending，不认证业务正确或批准行动。
- 审核完整请求body，包括system、user、response_schema与发送控制字段；密钥头只在进程装配，不记录请求完整headers。
- 不保存违反禁止内容的raw回复／错误body；只保留安全失败、范围和可用usage。合法校验后响应可保存，明确仍是草稿。
- .tmp同目录必要例外和报告自引用排除明确；不覆盖旧run或因扫描不便删证据。
