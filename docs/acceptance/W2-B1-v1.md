## 3. 测试与证据纪律

- 每个主要反向以可接受合法基线为起点，只改变一个条件；不得用多个累积错误解释独立覆盖。
- 缺件由新合成包创建时省略，不删除／移动旧证据。
- 功能 CLI 故障走真实发布路径；受控 patch 范围明确，失败残留保存，不把 mock成功当真实发布成功。
- 数字与哈希由工具计算；测试期待可来自工具生成 fixture 真值或固定口径元数据，不把手写生产数值当新实测。
- 只读保护摘要证明当前执行窗口，不要求或补造历史运行前摘要。
- 产物清单只枚举批准阶段／批次路径；报告自引用摘要排除明确，不无限重写、不笼统豁免产品输出。
- 先合成回归，成功后才单独批准固定真实入口；成功候选呈现后才请求实际 S3 决定。技术批准与业务批准分开。
- 禁止为测试使用真实危险网络、原始 CSV、未授权路径、原始行提示词或删除操作。
- Python观察不宣称native／全系统隔离、身份认证或协同篡改防御。
