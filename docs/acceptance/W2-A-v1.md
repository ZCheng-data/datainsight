## 1. 目标、输入与边界

唯一闭环：结构化问题＋已验收历史画像 → 离线确定性诊断 → 待人工决定 → 独立、版本绑定的 S2 决定记录。

正向方法只纳入原始记录按 behaviour 代码分类计数的前提检查。GMV 和严格漏斗只用于缺口／范围诊断，不自动改写问题，不生成分析结果。

生产输入固定为 `outputs/W1-B/final-20261009T061339601505Z/production/` 下画像与固定关联文件、本地最终验收记录及读取契约。完整读取清单以方案第 3 节为准。原始 CSV 不属于 W2-A 执行读取范围。

历史生产没有修复后 final-status，采用精确来源的已验收特例；修复后合成收尾证据不能冒充新生产运行，也不补造旧终态。新协议画像必须有合法成功终态，测试该分支使用合成包。

写入候选：新实现／合成测试只限方案第 6 节；新运行证据只限 `outputs/W2-A/<run_id>/`；一般临时产物只限 `outputs/_scratch/` 或 `.cache/tmp/`；原子发布 `.tmp` 必须在目标 run 同目录，属于 ADR-003 必要例外，不是待清理项。上述候选范围均须取得执行动作权限。

依赖：项目现有 Python venv；W2-A 仅标准库，不启动 DuckDB，不安装任何包。W1 回归如涉及既有 DuckDB 仅复用现有环境，不重装、不运行生产画像或历史安装脚本。

非目标：自由 SQL、生产重跑、清洗、S3–S6、模型／API、费用实测、任意目录发现、全系统网络隔离或协同篡改防护。

## 3. 证据与运行要求

- 新批次证据目录：`outputs/W2-A/<run_id>/`；run_id 由工具生成并记录，不以本文生成日期冒充运行时间。
- 诊断证据至少含输入 manifest、问题／规则身份、诊断、引用核验、命令、环境、网络观察和最终状态。
- 决定证据存新 run，引用成功诊断，不回写已完成诊断或旧 run。
- 所有哈希、业务值、测试项数、耗时与退出状态均由实际工具输出提供。预算／设计限额与实测值分别标注。
- 本轮不要求新的 CSV 哈希；只读历史画像的版本绑定不是“当前源仍一致”的证明。
- 保留源 SQL／工具证据链接用于可信重跑，但本轮不运行这些 SQL；已有生产计算与合成收尾继续分别标注。
- 受控反向测试只用 fixture／mock，不扫描未授权目录、不测试真实危险网络或破坏操作。
- Python 网络／调用观察不宣称 DuckDB 原生或全系统隔离；W2-A 不启动数据库引擎。
