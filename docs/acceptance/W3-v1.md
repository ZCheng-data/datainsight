## 1. 必须演示的闭环与能力边界

固定有效S3 approve → 独立G3.5“不清洗／原始记录全保留”决定 → 独立当次真实读取许可 → 唯一`M-BEHAVIOUR-RECORDS`计算 → S5执行／口径／边界三层通过 → 本地报告草稿与唯一终态 → 一次W3技术验收。

使用阶段已有部分证据——历史生产画像与模板重跑、源前后身份一致、真实S2 accept及S3方案／口径approve；**尚无完整S4→S5→S6真实业务结论闭环**。

真实版本上的行为代码原始记录计数及限定描述是本轮必需证明场，不是加分项。W3通过必须有新增获批真实计算／校验／草稿，不能只用旧画像数字或合成测试。

W3到S5，report为draft，human_review_state=pending。独立S6人工业务解释确认在其后；完成它之前不能宣称完整S4→S5→S6闭环。S6确认与外发许可分开。

## 2. 已确认的设计范围

仅现有问题／唯一方法／完整口径；不新增方法、双口径、自由文本翻译、受控问题路径入口、自由SQL、模型或预算功能。

资源设计值不是实测：局部DuckDB memory_limit=256MiB、threads=1，E3总体deadline180秒；固定聚合单结果64KiB、每个JSON／草稿1MiB边界。超时或配置不符停止，不能自动提高上限。只允许固定本模块worker监督查询，不宣称OS级总内存或全系统隔离。

所有新文件／环境／可控缓存在批准D盘范围。原数据只读，SELECT／WITH仅受信固定模板；禁DDL／DML／ATTACH／COPY／INSTALL／LOAD／SET等。

## 4. 最小证据包

采用方案中的strategy.json／bindings.json／operation.json／final-status及E3的result.json／calculation-evidence.json／validation.json／report.md。可以集中字段，不为每项另建一个证明文档。

- 必需输入／结果／口径／模板实际字节hash、可重跑SQL／参数、固定源引用、实际argv／退出码、Python／DuckDB版本、批准范围及工具记录时间。
- 合成test.log与case-results记录实际预期／结果和主要拒绝／故障断言；可含独立参考工具结果，不输出原始行／标识值。
- 不要求跨run完整逐文件清单、哨兵扫描范围报告或同一结论反复独立恢复核验；不取消必要输入核验／安全拒绝测试。
- 不重算W1／W2全量hash，不审计全部历史outputs，不跑旧安装／画像／回归runner。
- 生产计算与合成测试分别列示；新W3真实计算不能回填成W1修复后生产运行。

## 5. 权限、冻结与判定

本标准已与方案／交接合批获用户确认并保存frozen状态；D301–D312及设计内容未变，标准确认不授权执行。低档执行批范围、准确命令／cwd／环境、首次＋至多一次合成重跑与限定修复仍须另获预授权；次数耗尽、新依赖／上限／旧功能变更停止。

真实摘要读取、G3.5人工门和当次CSV读取独立；E3真实运行最多一次，失败后的读取／重跑必须再批。S6决定在W3后独立，外发仍独立。

状态规则：无运行证据为未验收；离线通过仅为E3-REAL前置，不代表D312。W3总通过须D301–D312全部满足；数值、权限、隐私、来源、预算适用或终态阻塞不有条件放行。失败保留新run并给最小修复范围，不放宽标准。

运行结果另存`docs/acceptance/results/<w3_run_id>.md`，INDEX分别标离线／真实／失败，执行者不自行通过。未来变更资源数值、方法、口径或范围保留frozen旧版并新增版本／必要ADR，不把失败当自动放宽理由。

本次冻结不产生新的业务数值、运行结果或完整案例验收结论。当前只保存标准确认／冻结及规划接口状态；W2旧C205保持未满足，W3不触发它。
